状态：已真实验证凭据读取、场次查询、单目标及同一时段两场提交；跨时段重测也有两笔提交成功（2026-09-16）。尚未完成独立订单查询，不宣称支付链路已验收。

## 一键启动

Windows 安装 uv、Clash 开启本机 HTTP 7897 后，双击 **start_booking.bat**。
入口在项目目录执行 `uv sync --locked`，只使用本项目 `.venv`；不依赖参考仓库的运行环境、不向全局 Python 安装包。

1. **刷新凭据**：菜单 1，输入 1（开始捕获），再手动进入企业微信 → 工作台 → 南邮小程序 → 体育场馆 → 羽毛球。只捕获自己的会话。CA 信任首次配置见 SESSION_GUIDE.md。
2. **验证**：菜单 2，服务端只读验证成功后继续。
3. **配置**：菜单 3，填写日期、场馆、时间，按序号填写候选场地、数量。仅保存，不提交。
4. **立即预约**：菜单 4，核对目标后输入 1（确认预约） 才提交。
5. **定时预约**：菜单 5，填写完整北京时间日期及时间，最多提前一小时启动。先刷新凭据，保持电脑唤醒；不承诺秒级 HTTP Date 可以校准到毫秒。
6. **只读测速**：菜单 6，三次类型查询，显示 RTT 和网关 Date 粗略误差，不占场。
7. **本地结果**：菜单 7，显示提交结果和估算支付剩余时间，不显示凭据/订单号。
8. **代理恢复**：菜单 8，用于强制关闭/断电后恢复抓包前设置。
9. **放场观测**：菜单 9，根据配置查询20轮、每轮至少3秒，只记录状态变化，不提交。

如已手动启动 mitmdump，先在其窗口 Ctrl+C 释放8080。Clash 保持运行及7897端口，但不要在捕获期间自动把系统代理改回7897。
菜单1会备份系统代理，限定南邮域名解密，结束时恢复；不要分享 CA 私钥或 private 目录。

## 任意时段、多场与候补

每组目标包含：准确日期、起止时间、完整场地名列表、数量。仙林场地先按新馆3楼双打、3楼单打、体育馆1楼、训练馆2楼排序；同一档按你的输入顺序。

- 同一时段要两场：配置一个组，数量2，选择至少两块场地。
- 两个时段各一场：配置两个组，各数量1。
- 只要一场但可换场：一个组，数量1，选择多个候选；不是把候选全预约。
- 当前上限：6组、总需求不超过6场。平台实际限制更严格时立即停止。

配置保存在 private/plan.json（version 2），不是早期的 example.yaml。
算法每次读取实时列表，只在指定时段/场地内选择。以最大匹配为各目标保留可行场次，优先处理候选更少的组；同等情况下遵循仙林分档优先级和档内配置偏好。它不是对其他用户行为的预测，也不能保证全局最优抢场成功率。

## 重试、安全边界与状态

- 一个请求在途，所有API请求起始间隔至少1秒；复用Session，缓存羽毛球类型ID。
- 最多20轮查询、60秒调度窗口；在途请求可能使退出晚于窗口，单请求连接/读取超时5/8秒。
- 每组最多 max(3, 数量) 次提交尝试；同一场次一轮只提交一次。
- 明确售罄：重新查询后选择其他候选，不依赖旧页面。
- 网络超时、HTTP异常、成功响应字段不匹配：结果未知，停止所有新提交；先人工核对小程序。
- 未付款限制、账号限额、限流、登录异常：停止，不自动换账号或重试规避。
- 成功后保留已有订单，立即提醒；不自动付款或取消。五分钟从提交前估算，最终以小程序为准。
- 提交前持久化意图；原子写入记录；进程锁阻止重复启动。历史成功场次不会自动重订，即使你后来取消或过期。
- 历史未知状态会阻止新的执行。当前没有独立订单查询或自动解除拦截，须人工核查后再由维护者处理记录，不能直接删除 private 来强行重试。
- 三次小样本测速和午后查询不能证明12:00放场时刻；观测记录表示客户端采样边界，不是服务器内部时间。

## 详细帮助与仙林优先级

菜单10（完整帮助）可在终端读取 USAGE.md，涵盖全部菜单、每个输入字段、两个组的填写步骤、输出状态、配置文件含义和异常处理。

优先级按用户提供的分类实现：仙林体育馆3楼1–8号（双打） > 3楼9–12号（单打） > 体育馆1楼任意 > 训练馆2楼任意。3F/3楼/中文场号均可识别，未知名称排后且不猜测。仅在已选候选中生效，旧配置运行时也使用这一排序，不自动扩大候选范围。同档仍保留输入顺序；多组竞争时最大匹配会优先确保有可行场次，不能保证全局提交顺序严格按楼层。
