# NJUPTBadminton — 本机预约助手

当前操作与限制以 [USAGE.md](USAGE.md) 为准。2026-10-10 P0修复和P1实测见 [P0_P1_REPORT.md](P0_P1_REPORT.md)。

## 日常操作

1. 首次安装使用 `setup_environment.bat`（uv与项目虚拟环境，不装全局包）。日常双击 `start_booking.bat`，不重复同步环境。
2. 菜单5刷新本人凭据，按提示临时抓包；手动从企业微信进入小程序场馆页面。成功自动恢复代理，不显示令牌。
3. 菜单6只读验证登录。菜单3设置每日时段；最多两个目标组、总共两场。
4. 菜单4 → 3设置焦点时段、3楼场号与覆盖/指定场模式。
5. 菜单1确认当天12点定时预约；确认前到小程序核对账户剩余名额。
6. 11:57:30重新校时，11:58:50截止；11:59准备当天候选，12点提交。成功后自行支付。
7. 菜单11查看只读诊断；不要为了重跑删除未知订单记录。

“窗口已打开”不代表已确认定时预约。重复启动保留原窗口，不会杀掉正在预约的任务。凭据过期需要重新刷新；目前没有无人值守续期或每日计划任务。

## 当前提交策略

- 默认覆盖优先，真正按目标轮转；不按候选排名假装轮转。
- 默认焦点为第一目标的新馆3楼6号；焦点场实际参与排序，并在焦点时段优先于普通档位。
- 其他候选默认：3楼双打1–8 → 3楼单打9–12 → 体育馆1楼 → 训练馆2楼。只使用当天接口返回的、配置允许的候选。
- 一个请求在途，默认全局请求开始间隔1秒。这是本地保守策略，不是已核实的平台许可频率。
- 成功停止该时段；未知结果、登录/限流/额度/风控问题停止全局。不会自动支付、取消、升级已成功场地。
- 仅**明确尚未开放**且没有订单证据时，全轮允许一次开抢后三秒内的边界重试；含糊时间提示和“预约窗口之外”不能触发。
- 准备查询每天一次；所有恢复分支共享一次GET预算。首轮不插入GET；明确连续售罄或候选耗尽时才考虑恢复查询。预算耗尽后停止，不轮询。
- 总目标最多2场。历史未知结果阻止重跑，已知本地未来/当天成功订单保守占用名额；本地记录不是实时账户完整订单清单，需要用户人工核对。

## 安全与计时

TLS始终验证；不记录令牌、Cookie、签名、完整认证信息。`private/`被Git忽略并受本机目录权限保护。

开抢前预构造Requests请求、静态字段与签名前缀，签名时间戳仍在限速等待后生成。提交意图提前持久化，不能为省毫秒删除。末尾最多0.5ms本地短自旋，不调高系统优先级、不更改系统时间、不提前发送。

本机参考时间不是服务端业务时间；HTTP Date只有秒级旁证价值。离线适配器入口基准不含DNS/TCP/TLS、传输与服务端排队，不承诺首选命中率或服务器收包毫秒。

## 本地诊断和复测

以下命令在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe task_runtime.py diagnose
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe perf_benchmark.py --samples 100 --output private/perf-local.json
```

前两条无网络。离线基准需要本机 `private/performance-baseline-20261010` 中保存的优化前源码快照；该目录不随Git提交。

有明确测速需求时才执行：

```powershell
.\.venv\Scripts\python.exe perf_routes.py --network --output private/perf-routes.json
```

此命令对公开根页面交替最多5次/路径GET、间隔3秒，无凭据、不访问预约POST；不能替代预约接口高峰测试。HTTP错误响应不计为有效速度样本。2026-10-10两路均HTTP502，因此未据此切换出口。

`api.py`负责通信与分类，`booking.py`负责订单状态机，`serial_queues.py`负责候选轮转，`daily.py`负责定时准备。第三方参考仓库和此项目独立管理。
